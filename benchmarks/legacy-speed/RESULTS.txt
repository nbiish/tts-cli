# Legacy TTS Speed Benchmark — KittenTTS & PocketTTS vs IndexTTS-2.5
# Date: 2026-08-31  |  Host: Apple Silicon (M-series), macOS  |  Cold-start, one-shot (no daemon)

## 1. Purpose
Benchmark the legacy engines (KittenTTS, PocketTTS) that were removed from tts-cli
against the current IndexTTS-2.5 tiers, and survey the 2026 TTS landscape, to
decide which model is the fastest / most performant for the agent end-of-chat
voice-summary use case. Constraint: cross-platform (macOS / Linux / Windows /
WSL), models fully unloaded from RAM/VRAM after every call (cold start every
time, no warm daemon).

Input text (166 chars), identical for every engine:
  "Task complete. I integrated the IndexTTS engine and verified the fast path
   loads clean. Next step: audit the supply chain provenance and lock down the
   secrets bundle."

## 2. Measured results (this machine, cold load + generate, wall clock)

  Engine                          | cold wall | audio dur | RTF   | voice source
  ------------------------------- | --------- | --------- | ----- | --------------------
  KittenTTS nano int8 (15M, 25MB) |    7.93 s |   16.73 s | 0.47  | built-in expr-voice-5-m
  KittenTTS mini (80M, 80MB)      |    9.49 s |   14.30 s | 0.66  | built-in expr-voice-5-m
  PocketTTS english (CPU, clone)  |   11.64 s |   10.44 s | 1.11  | clone examples/default_voice.wav
  IndexTTS-2.5 GGUF Q8 (Metal)*   |   ~43 s   |    ~8.4 s | ~5.1  | clone examples/default_voice.wav
  IndexTTS-2.5 Python (MPS)*      |   ~142 s  |    ~8.3 s | ~17.2 | clone examples/default_voice.wav

  * IndexTTS-2.5 numbers are from the prior benchmarks/indextts-prompting/RESULTS.txt
    (same hardware, same cold-start-one-shot policy). Lower wall = faster;
    RTF = wall/audio_dur (lower is faster; <1 means faster than real-time).

  Notes:
  - KittenTTS has 8 FIXED built-in voices (expr-voice-2..5 m/f). It does NOT do
    zero-shot voice cloning — it cannot reproduce an operator reference clip.
  - PocketTTS DOES zero-shot voice cloning (matches the tts-cli --voice design)
    and runs cross-platform on CPU (Python/torch). On Apple Silicon it also has
    a CoreML/ANE path (see §3) that is far faster than the CPU path measured here.
  - All three legacy engines run on CPU — no GPU/MPS required — so they satisfy
    the cross-platform constraint on Linux/Windows/WSL out of the box.

## 3. 2026 landscape survey (web search, 2026-08-31)

Picovoice "On-device TTS Comparison: Open-source Benchmark 2026"
(https://picovoice.ai/blog/on-device-tts/) — first-audio time (FTTS), lower=faster:
  Picovoice Orca        106 ms   streaming in+out   41 MB   7 MB peak   (GPLv3, commercial)
  Soprano TTS         1,702 ms   streaming out     280 MB
  Pocket TTS          1,713 ms   streaming out     242 MB   610 MB peak  (MIT)
  Piper TTS           1,720 ms   streaming out      61 MB   2.6 GB peak (MIT, fixed-voice)
  Supertonic TTS 2    2,612 ms   streaming out     262 MB
  Neu-TTS-Nano Q4     2,952 ms   streaming out     507 MB
  Kokoro TTS         3,658 ms   streaming out     341 MB   2.0 GB peak  (Apache-2.0, fixed-voice)
  Kitten TTS Nano   10,483 ms   single synthesis    42 MB   320 MB peak  (Apache-2.0, fixed-voice)
  Chatterbox-TTS-Turbo 48,281 ms  single synthesis 2,980 MB 7.5 GB peak

  -> PocketTTS is the fastest OPEN zero-shot-cloning engine in the field.
     KittenTTS is the smallest but is NOT a speed leader once loaded (no streaming,
     10.5s FTTS) — its win is footprint, not throughput. Picovoice Orca is the
     absolute fastest but is GPLv3/commercial (not a fit for this repo's stack).

PocketTTS v2.0 (Apr 2026, https://github.com/kyutai-labs/pocket-tts release v2.0.0):
  - Multi-language (english_2026-01/04, italian, german, spanish, portuguese, french_24l)
  - --language selects the pretrained model; --quantize for ~30% speedup on the 24-layer models
  - English model = 6 layers, ~242 MB

PocketTTS v2.1 CoreML/ANE (FluidInference PR #665, macOS 26):
  - Fused flow decoder + cond prefill + fp16 flowlm -> ~452-520 ms / utterance (~1.8x RTFx)
  - Apple-Silicon-only optimization; the plain Python CPU path (measured above)
    remains the cross-platform default on Linux/Windows/WSL.

PocketTTS macOS / Mimika (https://github.com/2b3pro/pocket-tts-macos):
  - Native Swift/CoreML app; ~0.17s first-audio, ~3x real-time, Pocket-TTS ~2.9x realtime.
  - Confirms PocketTTS is dramatically faster than IndexTTS on Apple Silicon.

## 4. Recommendation

For the agent end-of-chat voice-summary use case (cross-platform, zero-shot clone
of an operator reference voice, cold-start every call, models fully unloaded
after each call):

  FASTEST + MOST PERFORMANT FIT: PocketTTS (kyutai-labs/pocket-tts, MIT).

  Why:
  - It is the fastest OPEN zero-shot-cloning engine in the 2026 field (1.7s FTTS).
  - It does voice cloning (matches the existing --voice / examples/default_voice.wav
    design) — KittenTTS cannot clone and would force fixed voices.
  - It is cross-platform on CPU (Python/torch): works on macOS, Linux, Windows,
    WSL with no accelerator. On Apple Silicon it has an optional CoreML/ANE path
    (~1.8x RTFx) for even more speed.
  - Measured here at 11.6s cold (RTF 1.11) vs IndexTTS-2.5 GGUF 43s (RTF 5.1) —
    ~3.7x faster cold and ~4.6x better RTF, with cloning preserved.
  - License (MIT) is compatible with the repo.

  KittenTTS nano int8 is the absolute fastest cold start measured (7.93s, RTF 0.47)
  and the smallest (25MB), so it is the best FALLBACK when no reference voice is
  available (fixed built-in voices) or on the most constrained CPU-only hosts. It is
  not the primary recommendation because it cannot clone the operator's voice.

  IndexTTS-2.5 remains the QUALITY tier (highest-fidelity multilingual cloning) but
  is the slowest (43s GGUF / 142s Python cold). Keep it as the --quality option, not
  the default, for the agent-summary path.

  Suggested default ladder for tts-cli:
    1. auto / index-tts  -> PocketTTS (fast default, cloning, cross-platform CPU)
    2. --quality         -> IndexTTS-2.5 (full-precision, multilingual, highest quality)
    3. --voice <ref.wav> works for both PocketTTS and IndexTTS; KittenTTS ignores it
       and uses a built-in voice (document this).

## 5. Caveats
  - Numbers are from a single cold run per engine on one Apple Silicon host; treat
    as directional, not a statistically tight comparison. Re-run bench_legacy.py to
    refresh.
  - PocketTTS CPU RTF (1.11) is slower-than-realtime on this CPU path; the CoreML
    path is needed for sub-realtime on Apple Silicon. On Linux/Windows/WSL the CPU
    path is what you get (still ~3.7x faster than IndexTTS-2.5 GGUF cold).
  - KittenTTS "fast" FTTS in the Picovoice table (10.5s) looks slow because it does
    single full synthesis (no streaming); its cold wall here (7.9s) is low because
    the model is tiny and loads instantly. Good for short agent summaries.
